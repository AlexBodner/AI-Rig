## Issues — RIGOR and OVERCLAIM

### C10 — fatal — PROVED-HERE is not defensible for a scaling heuristic

C10 is the load-bearing claim of the line: `5/6` (the realized threshold), `5/4` (the front threshold), the `(d+2)/4` dimension corollary, the C8 stall law, the 2.10 transfer row and both breakpoints all descend from it. Its proof consists of a hypothesis that is not a mathematical statement ("call `A(n)` the amplitude of shell `n` at the moment at which it is the active (energy-carrying) shell of the cascade, and suppose the cascade advances one shell per turnover, so `T_{n+1} - T_n ~ 1/(lam^n A(n))`"), three "facts" of which two are stated with `>>`, and a "QED". Fact 1 is worse than imprecise: "`sum_n 1/(lam^n A(n)) < infinity` iff `A(n)` decays slower than `lam^(-n)` up to summable corrections" is circular — the qualifier is doing all the work, and the literal claim is false (`A(n) = lam^(-n) n^(-2)` decays faster than `lam^(-n)` by a summable factor and gives a divergent sum, while `A(n) = lam^(-n) 2^(eps n)` with `eps > 0` gives a convergent one). Verified by re-deriving each of the three facts and testing fact 1 on those two families. The scaling content is correct and useful, and one genuinely provable statement sits inside it — for a power-law family `A(n) = c 2^(-bn)` the ratio `lam^n A(n) / (nu 2^(2sn))` tends to infinity iff `b < 5/2 - 2s`, which is PROVED-HERE arithmetic — but the dichotomy as written, applied to "the cascade" rather than to a power law, is a heuristic. Accepted status: **CONJECTURE**, with the power-law inequality split off as PROVED-HERE. Every downstream statement that says "by C10" inherits this, including the 2.10 transfer row's "the mechanism saturates Lions' exponent and cannot violate it, in any dimension", which is presented as a structural theorem.

### C2 — major — the scaling Proposition is false on the half-lattice the file defines

"Setting and notation" fixes the model on `n >= 0` with `a_{-1} = 0`. The Proposition then says `b_n(t) := mu a_{n+1}(sig t)` "solves the model with the same `nu` and `s` whenever `a` does". At `n = 0` this is false: the model at shell `0` has no inflow term, but `db_0/dt = mu sig (da_1/dt)(sig t)` contains `mu sig lam a_0(sig t)^2 = mu^2 a_0(sig t)^2`, which vanishes only if `a_0 == 0`. So the residual at the boundary shell is exactly `mu^2 a_0^2`, nonzero for every solution started from the file's own initial condition `a_0 = 1`. The same omission propagates to the corollary "under this map `E -> 2E` and `H^1 -> H^1/2`": the correct half-lattice identities are `E(b) = 2(E(a) - a_0^2)` and `H^1(b) = (H^1(a) - a_0^2)/2`. Script part 1c does not catch this because it checks a single interior shell (`i0 = 3`) of an 8-shell array. Verified by hand and by the residual computation above. The claim is true with the added hypothesis "on the bi-infinite lattice `n in Z`" (or "for interior shells"), and nothing downstream breaks, since every later use is asymptotic in `n`. Accepted status: **PROVED-HERE with the bi-infinite hypothesis stated**.

### C6 — major — the "H^1 just before escape" column is not what the notes say it is, and its constancy is an artifact

The notes' C6 table reports `H^1` "just before escape" as `2.0933` for every `N` from 16 to 32 and never comments on it; a reader takes this as evidence bearing on the open question the same section poses, namely whether `H^1` is finite at `T*`. The code prints `r["H1"][-2]`, the value at the last `t_eval` grid point, and that grid (`np.logspace(-14, log10(t_end), 1500)`) is identical for every `N`, so the printed number is the state at the fixed time `t = 0.0820928` — about `7.6e-4` before the event, an eternity on the scale of the front's last twenty shells. Its constancy across `N` is therefore automatic and carries no information. At the event state itself I measure `H^1 = 2.1801, 2.1839, 2.1841, 2.2021, 6.7961, 1182.78` for `N = 16, 20, 24, 28, 32, 36`, of which the last-shell contribution `4^(N-1) * (1e-9)^2` alone is `0.0000, 0.0000, 0.0001, 0.0180, 4.6117, 1180.59`. So the event-time `H^1` is dominated by the arbitrary escape threshold and is equally uninformative. Verified with a scratch script calling the author's own `run()`. Neither number should be presented as a diagnostic; the C6 sub-question remains open for the reason the notes give, but not for the reason the table suggests.

### C6 — major — the stated cause of the outer-slope drift has the wrong sign

The notes label the profile question FAILED and give the breaking step as "the outer window needed to see the asymptote is pushed past `N = 32` by the exponentially small precursor tail of C4, whose slope `-5/2` contaminates the last shells". A contaminating `-5/2` tail biases a least-squares slope **steeper**, i.e. more negative; the observed drift is monotonically **shallower** (`-1.5552, -1.5159, -1.4032, -1.2623`). Dumping the `N = 32` profile at the event state gives per-shell log2 differences of about `-1.55` through shell 19 and then `-1.09, -0.95, -0.90, -0.79, -0.95, -0.62, -1.25, -0.01, -2.48, +2.46, -7.43` across shells 20 to 31 — a non-monotone shoulder at the truncation boundary, not a `-5/2` tail. (The shoulder is genuine, not solver noise: it is identical to three significant figures for `rtol` from `1e-7` to `1e-12` with `atol` from `1e-14` to `1e-20`.) The diagnosis should be the truncation boundary layer — shell `N-1` has no drain, so the last several shells behave differently from the infinite system — which is a different, and less easily fixed, obstruction than the one recorded.

### C8 — major — "locates the blowup threshold to about one percent" is an unsupported precision claim

The fitted line is `1/slope = 2.0803 s - 1.7571` against the prediction `2 s - 5/3`: the slope is off by `4.0 %` and the intercept by `5.4 %`, and the root lands `1.4 %` from `5/6` only because the two errors partly cancel. The fit has four points, all at `s` in `[1.00, 1.40]`, and the root at `s* = 0.8446` is an extrapolation well outside that interval. The dependent variable `n_d` is an integer (`argmax` over shells of the dissipation spectrum), so each of the sixteen underlying measurements carries at least half a shell of quantization; no uncertainty is propagated anywhere. Verified by recomputing the fit and its residuals from the script's own printed `n_d` values. The honest statement is that the measurement is consistent with `5/6` at the few-percent level; "locates the blowup threshold to about one percent, rather than a binary verdict that a truncation could fake" overstates what four extrapolated integer-valued points can support. Accepted status: **COMPUTED, consistent with `5/6` at the few-percent level**.

### C8 / C9 — major — "the model is regular throughout `s > 5/6`" is a category error from truncated runs

Every system integrated here is a truncated, finite-dimensional ODE with the exact energy identity of C1, hence `|a(t)| <= sqrt(E_0)` for all `t` and global existence is automatic: no truncated run can exhibit or exclude blowup of the infinite system. The only observable is whether the excitation reaches the last retained shell before `t = 200`, which the notes themselves identify as a false positive in three rows of C7 and in the `s = 0.8` row of C8. The stall evidence (an interior dissipation peak with `n_d < N - 6` and energy decaying by twenty to forty orders of magnitude) is good evidence, and I do not dispute the verdicts row by row; but C9's "the model is regular not only in the subcritical range `s >= 5/4` but throughout `s > 5/6`" is a claim about the untruncated system that the numerics cannot make. Accepted status for that sentence: **CONJECTURE** (or COMPUTED about the truncated systems), not a statement of regularity.

### C8 — major — the only positive "front escapes" data point is not truncation-independent either

C8 contrasts `s = 0.7` ("the escape time is truncation-independent, as it is for the inviscid model in C6, so the front genuinely reaches infinity") with `s = 0.8` (monotone drift, therefore a false positive). Running the same auxiliary sweep at `s = 0.7`, `nu = 0.274`, `N = 18, 22, 26, 30, 34` gives `T_esc = 0.0870, 0.0870, 0.0871, 0.0872, 0.0874` — monotone, still rising at `N = 34`, and about `0.5 %` across the range. That is the same qualitative signature the notes use to reject `s = 0.8`, differing only in rate; it is not "as it is for the inviscid model in C6", where `T_esc` is identical to seven digits from `N = 24` onward and my extension to `N = 36` changes nothing. The `1 %` convergence test hard-coded in `part4_threshold` is what separates the two rows, and it is arbitrary. So the sub-threshold side of the C8 picture rests on no truncation-independent escape at all; the whole threshold argument leans on the 4b slope law. Verified by the scratch sweep described above.

### C12 / Breakpoint 2 — major — an impossibility claim presented as established, under a KNOWN heading

C12 is tagged "KNOWN (survey of the obstructions)", but points 1 to 4 are largely the author's own reasoning, and two sentences assert impossibility: point 1's "that freedom is exactly what makes the gadget constructible for `B~` and not for `B`", and Breakpoint 2's "a gate needs a specific interaction to be *absent*, which the geometry does not permit". The second is false as stated: individual Euler trilinear coefficients `<B(psi_p, psi_q), psi_k>` do vanish for particular configurations (the Leray projector `P_k = I - k k^T/|k|^2` annihilates any vector parallel to `k`, and the factor `u_p . q` vanishes whenever `u_p` is orthogonal to `q`), so specific interactions can certainly be switched off; what is true is that the coefficients are not *freely* choosable as a family. The first is precisely the open question the line is about, and asserting it is exactly the kind of statement `00_problem.md` T1 warns against. Verified by writing out the coefficient formula `-i P_k (u_p . q) v_q`, which the notes give correctly, and exhibiting the two vanishing mechanisms. Accepted status for both sentences: **CONJECTURE**; accepted status for C12 as a whole: KNOWN for the cited facts, CONJECTURE for the inferences, which should be tagged separately as the section header promises ("with the specific comparisons tagged") but does not deliver.

## Issues — CITATION DEPENDENCE

This lens found five items to report against section 0 of `00_problem.md`, one of which is the second-most serious problem in the file.

### C7 / C9 / Goal / transfer rows 2.15 and T6 — major — the KNOWN status of the model's regularity at `s = 1` rests entirely on an admittedly unverified exponent range

The Goal section states flatly that "in the one-mode-per-scale class it is known not to beat the true dissipation (Barbato-Morandin-Romito 2011)"; C7's heading is "**COMPUTED** (reproduces a KNOWN theorem)"; the T6 row says the result "is explicitly labelled a reproduction of Barbato-Morandin-Romito 2011 and Cheskidov 2008". But the notes' own reference entry for BMR 2011 reads "an abstract snippet stating well-posedness of positive solutions of the viscous problem in the scaling range corresponding to Navier-Stokes; the exact range of exponents is unverified", and — decisively — under the notes' own inferred dictionary `alpha = 2s/5`, Cheskidov's stated thresholds give **global** regularity only for `alpha >= 1/2`, i.e. `s >= 5/4`, and only **local** regularity for `alpha > 1/3`. So Cheskidov does not cover `s = 1` at all, and the entire KNOWN status of "the dyadic model with the true Navier-Stokes dissipation is globally regular" hangs on one unread sentence of one abstract, plus an inferred normalization, plus the restriction to positive solutions. Section 0's rule ("no claim in this project may rest on the precise hypotheses of a cited theorem ... where an argument does depend on them, that dependence must be stated explicitly at the point of use") is violated three times over: the Goal says "it is known", C7's heading says "a KNOWN theorem", and the T6 row uses both citations as cover for the too-easy result. Verified by reading the notes' own reference entries against the dictionary in "Setting and notation". Accepted status: **COMPUTED for the truncated runs; the global-regularity statement is CONJECTURE pending a reader with library access confirming BMR's exponent range and solution class.**

### C6 — major — a `[checked via WebSearch]` tag carrying a mathematical identification

C6 writes "(KNOWN as a theorem: Katz-Pavlovic 2005 prove finite-time blowup for the inviscid dyadic model [checked via WebSearch: title, and that they prove blowup for the inviscid case])", and the reference list adds that Kiselev-Zlatos "the Katz-Pavlovic model blows up in finite time for any initial datum ... the first half is the theorem behind C6". Two unverified mathematical steps are hidden here: that the Katz-Pavlovic model is *this* model with *this* coefficient base `lam = 2^(5/2)` (the notes derive that base from Navier-Stokes scaling in C2 and never claim it is KP's), and that "blows up" in their sense (blowup of some Sobolev norm) is the same event as "the front reaches `n = infinity`" measured here by a threshold crossing at the last retained shell. The notes' own C6 admits `H^1` may well be finite at `T_esc`, which is exactly the gap between the two notions. The dependence must be stated at the point of use; as written the tag is carrying a theorem rather than a bibliographic fact.

### C9 — major — a claim about the internal structure of a proof that was never read

C9's self-test is justified by "Lions' theorem (no-go item 2.10) proves regularity for `s >= 5/4` and its proof, being an energy-plus-interpolation argument, covers averaged and dyadic analogues". `00_problem.md` item 2.10 tags Lions 1969 as "\[checked via WebSearch: book and the `alpha >= 5/4` attribution\]" — the book's existence and one attribution. Whether the proof is "energy-plus-interpolation" and whether it "covers averaged and dyadic analogues" are statements about a proof nobody in this project has read, and the second is in any case not literally true: a dyadic ODE system is not an instance of Lions' theorem, and one would have to redo the estimate. The self-test's *conclusion* (the measured threshold is far below `5/4`) is unaffected, but its stated justification is an unverified claim about an unread proof and should be either dropped or replaced by C10's own arithmetic, which derives the `5/4` internally.

### Setting and notation, and the C7 threshold table — minor — an inferred dictionary used as if it were read

The `alpha = 2s/5` dictionary is properly flagged as "**inferred**, not read off the paper", with two consistency checks that I verified (`alpha = 1/2` matches the energy-criticality exponent `s = 5/4` computed in C2; `alpha/alpha_crit = 2/3` matches `1/((d+2)/4)` at `d = 4`). But the table row that this justifies is headed "Cheskidov's proved blowup boundary `s = 5/6`", stated without a hedge, and C7 then reports "Cheskidov 2008 proves global regularity for `alpha >= 1/2` and blowup for `alpha < 1/3`" as a bare fact. Both should carry the inference at the point of use.

### The fluid-computer paragraph — minor — an exclusion is declined that is available in one line here

The paragraph says "any claim that these constructions are excluded from the Clay class of `00_problem.md` 1.1-1.3 on geometric grounds would be [unverified] and is not made here", after observing that the flat torus admits a nonvanishing harmonic 1-form. The caution is misplaced, because an exclusion is elementary and needs no reading of either paper: for unforced Navier-Stokes on `T^3` a steady solution obeys `0 = -nu int |grad u|^2`, so `u` is constant and carries no computation; and a nonzero time-independent force violates Fefferman's decay hypothesis (10). On the flat torus the harmonic 1-forms are exactly the constant fields, so the geometric condition is satisfied vacuously and yields nothing. The paragraph's conclusion (Turing completeness of steady flows gives no blowup, because steady solutions have constant norms) is correct and airtight; the hedge that follows it invites a reader to think the Clay setting is still open to these constructions when the problem statement itself closes it.

## Minor issues

For every item in this section and in the two minor transfer items below, the claimed status tag is accepted as it stands; the defect is in the description of what was computed, in a number that is not reproducible from the script, or in presentation.

The `N`-convergence to seven digits is real, but the limit as the threshold goes to zero is `0.0828478`, so the last quoted digit is wrong. Six digits are safe.
- **C8 — the auxiliary `s = 0.8` sequence is not in the script and I could not reproduce it.** The quoted `0.0895, 0.0917, 0.0941, 0.0964, 0.1040` for `N = 18, 22, 26, 30, 34` came out of my reconstruction as `0.0914, 0.0934, 0.0956, 0.0983, 0.1049` (tried both `nu = 0.274` and `nu = 2^(-14 * 2/15)`; all other parameters at the script defaults). The qualitative point — monotone drift — is unaffected, but a number quoted in a project with this file's reproducibility standard should be printed by the script.
- **C8 — scan 4a contradicts the law it is presented as illustrating.** `nu(s)` is said to be "chosen so that the predicted stall lands mid-range", and indeed `log2(1/nu)/(2s - 5/3) = 14` identically for every row. The additive constant in `n_d = log2(1/nu)/(2s-5/3) + const` therefore varies by about a dozen shells as the threshold is approached, which is expected (it hides `log2(eps^(1/3))/(2s-5/3)` and `eps` collapses near threshold) but is never said. The 4b fit is unaffected, since the constant cancels at fixed `s`.
- **C7 — two table entries silently report one truncation only.** For `(nu, A) = (0.3, 1)` the script gives `E_end/E_0 = 1.620e-40` at `N = 24` and `4.580e-41` at `N = 32`; for `(0.3, 3)` it gives `5.584e-42` and `8.769e-42`. The notes' merged rows print `1.6e-40` and `5.6e-42`, i.e. the `N = 24` values, while every other column in those rows is genuinely `N`-independent.
- **C1 — the notes misdescribe what the script checks.** "Script part 1a/1b verifies both identities symbolically for `N = 8` with `lam`, `nu`, `s` free" is wrong three ways: part 1a is inviscid and contains neither `nu` nor `s`; part 1b uses the dissipation `nu * lam^(2i) = nu * 2^(5n)`, i.e. the special case `s = 5/2`, not `2^(2 s n)`; and part 1c hard-codes `lam = 2^(5/2)` and prints the post-substitution residual only at `s = 1`. The identity is diagonal in the dissipation so nothing is actually at risk, but the sentence does not describe the code.
- **C7 — the positivity bound printed by the script is weaker than the one in the notes.** The script prints "min_n a_n >= -1e-15"; the notes say `-1e-18`. The notes are the accurate ones (the largest excursion in the fresh run is `-4.12e-19`), so this is a stale string in the code, not an error in the notes.
- **C4 — the analogy to no-go item 2.3 is loose.** The exact self-similar solution `a_n = lam^(-n)/((lam^2-1)(T-t))` has divergent energy because it grows as `n -> -infinity`, i.e. at the *large* scales, and it also violates the file's own boundary condition `a_{-1} = 0`; Necas-Ruzicka-Sverak and Tsai exclude profiles by their behavior at small scales and in `L^3`. Calling it "the model's analogue of no-go item 2.3" is a reading, not a correspondence, and the algebra (which is correct and does deserve PROVED-HERE) does not support it.
- **C11 — the heuristic step is a non sequitur, and Breakpoint 1 restates it as a fact.** "Its outflow rate `c_{j+1} a_{j+1}` must be small compared with its inflow rate `c_j a_{j-1}` during filling — informally `c_{j+1} << c_j`" drops the amplitudes, and during filling `a_{j+1}` is precisely the small quantity, so the conclusion about the coefficients does not follow. C11 discloses this ("Heuristic obstruction (the reason the conjecture is stated, not proved)"), but Breakpoint 1 restates it flatly as "the requirement ... needs the chain coefficients to decrease along the chain while scale invariance forces them to increase by `lam` per scale".
- **`maxH1` is a grid maximum.** `run()` evaluates on a fixed 1500-point log grid, so every `max H^1` in C7 is the maximum over that grid, not over the trajectory. At the stall this is harmless; it is worth one clause.

### C10 corollary and transfer row 2.8 — major — the `d = 2` case is inconclusive, not "T2 passing"

The dimension corollary computes `lam = 2^(1+d/2)` and the front-regime threshold `s < (d+2)/4`, both of which I re-derived and confirm. It then reads this as "transfer test T2 passing in a quantitative form: the mechanism does degrade exactly as the dimension drops". At `d = 2` the corollary's own arithmetic puts the true dissipation `s = 1` exactly *at* the front-regime threshold `(d+2)/4 = 1`, i.e. the maximal cascade is marginal, and a scaling comparison at marginality decides nothing. Since 2D Navier-Stokes is globally regular (no-go item 2.8) and the mechanism does not die there, the correct verdict for the maximal regime at `d = 2` is **inconclusive**; only the realized (constant-flux) regime, whose 2D threshold is `2/3 < 1`, degrades as claimed. The 2.8 row's own text is more careful ("not applicable as a faithful comparison; scaling arithmetic consistent"), so the overstatement is localized to the C10 corollary's final two sentences and to the T2 row's "Hyperdissipative: ... so it is dissipation-sensitive as required", which quietly generalizes to all dimensions.

### Transfer row 2.1 — minor — "force" is doing unearned work

The 2.1 row says the model's regularity "uses positivity and the one-way flux structure of C5, which force the constant-flux profile". That the constant-flux profile is forced is not proved anywhere in the line; it is exactly the statement the "What would be needed next" section proposes as an open problem ("Prove that for every chain model with positive coefficients and scale invariance, the front amplitude obeys `limsup 2^(5n/6) A(n) < infinity`").
